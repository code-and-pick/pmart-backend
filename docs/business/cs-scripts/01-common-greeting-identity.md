# 공통 응대: 첫 인사, 본인 확인, 주문 확인, 마무리

상담 시작부터 끝까지 모든 상황에 공통으로 쓰는 응대 절차와 문구입니다.

- 문서 버전: 0.1
- 작성일: 2026-11-09

## 1. 본인 확인 원칙 [채택 설계]

(사용자 승인 2026-11-28) — 상담 시작 때 개인정보 이용 동의는 따로 받지 않는다. 아래처럼 다른 사람에게 전달해야 할 때만 동의를 받는다.


- 개인정보(주소·연락처·결제정보)를 상담원이 먼저 말하지 않습니다. 상대가 말한 내용을 화면 정보와 맞춰 봅니다.
- 처리 과정에서 개인정보를 다른 사람(라이더·잘못 받은 사람 등)에게 전달해야 하면 **동의를 받은 뒤** 진행하고 상담 기록에 남깁니다([10](10-records-notifications.md) §1).
- 본인 확인에는 **주문 확인**이 들어갑니다. 문의 내용에 따라 무엇을 묻는지 달라집니다. 예: 누락이면 "빠진 상품", 오배송이면 "받으신 상품".
- 질문은 한 번에 묶어 묻습니다(두 가지를 한 문장으로).

## 2. 고객 본인 확인 [채택 설계]

(사용자 승인 2026-11-28) — 문의 종류별 본인 확인 표 승인.


| 문의 종류 | 발신 번호로 회원 조회됨 | 조회 안 됨 |
|---|---|---|
| 주문·취소·배송·반품 | 1. 주문하신 상품(또는 주문 일시) 2. 주문자 본인 여부(아니면 관계) | 1. 주문자 연락처 2. 주문하신 상품(또는 주문 일시) 3. 주문자 본인 여부(아니면 관계) |
| 회원·계정·기타 | 1. 회원 본인 여부 2. 로그인한 소셜 계정 종류 또는 가입 이메일 | 1. 가입 연락처 2. 회원 본인 여부 3. 로그인한 소셜 계정 종류 또는 가입 이메일 |

- 주문·취소·배송 문의는 주문자 본인이 아니어도(대신 받는 가족 등) 상담할 수 있습니다. 관계를 기록합니다.
- 회원·계정 문의는 본인이 아니면 상담하지 않습니다.
- 연락처는 셋이 다를 수 있습니다: 지금 건 번호, 회원 연락처(가입 때), 주문 연락처(주문 때).
- 결제 후에는 주소·연락처를 바꿀 수 없으므로, 배송 문제를 확인할 때는 **주문 당시 주소**를 기준으로 봅니다([확정 정책] `OMS-business-logic.md` §4).

## 3. 라이더 본인 확인 [설계안]

라이더가 배송 문제로 연락했을 때입니다.
- 1. 라이더 이름 2. 배송 중인 주문번호 뒷자리(또는 MFC 이름과 인계 시각)
- 라이더 지급·평가 문의는 라이더 지원 창구로 안내합니다. 상담원이 지급·공제를 정하지 않습니다(`BackOffice-business-logic.md` BO-21).

## 4. 주문 확인 [채택 설계]

(사용자 승인 2026-11-28) — 해당 주문의 고객이 맞는지·해당 주문이 맞는지 묻는 절차와 문구 승인(§5 의 본인 확인 두 문구 포함).


주문을 정확히 집어야 할 때(취소·반품·오배송 등) 묻습니다.
- 고객: 주문하신 상품 또는 주문 일시·금액
- 라이더·MFC: 주문번호 뒷자리 4자리

문구:
- "확인 원하시는 주문이 000원, 000시 주문 맞으실까요?"
- "주문번호 뒷자리 0000 주문 맞으실까요?"

## 5. 첫 인사 [설계안]

- 고객: "안녕하세요, PMart 고객센터 ㅇㅇㅇ입니다. 무엇을 도와드릴까요?"
- (회원 조회 안 됨) "연락주신 번호로는 조회가 되지 않아, 주문하실 때 입력한 연락처 말씀해 주시겠습니까?"
- (한 번에 확인) "확인을 위해 주문하신 상품과 주문자 본인 여부 말씀 부탁드립니다."
- 라이더: "안녕하세요, PMart 고객센터 ㅇㅇㅇ입니다. 배송 중인 주문번호 뒷자리 말씀해 주시겠습니까?"

## 6. 상황별 공통 문구 [설계안]

| 상황 | 문구 |
|---|---|
| 불편을 말했을 때(본인 확인 전이라도 먼저) | "불편을 드려 죄송합니다. 확인 후 도와드리겠습니다." |
| 본인 확인이 끝났을 때 | "확인 감사합니다." |
| 화면·MFC·라이더 확인이 필요할 때 | "확인을 위해 잠시만 기다려 주시겠습니까?" |
| 기다린 상대에게 | "기다려 주셔서 감사합니다." |
| 취소·환불을 **접수**했을 때 | "요청 접수되었습니다. 처리 결과는 앱 알림으로 안내드립니다." — 완료라고 말하지 않습니다 |
| 결과가 아직 확인 중일 때 | "현재 처리 확인 중으로, 결과가 나오면 앱 알림으로 안내드리겠습니다." |

- **"완료"는 결과가 확정된 뒤에만** 말합니다. 취소는 출고 중지 확인과 결제 취소 성공, 환불은 결제 취소 성공 뒤입니다([채택 설계] `OMS-business-logic.md` §8.4, §10).
- 같은 문제로 이미 접수된 건이 있으면 새로 접수하지 않고 **기존 접수의 진행 상황**을 먼저 안내합니다(`Commerce-business-logic.md` §13.2).

## 7. 마무리 [설계안]

- (긍정적으로 끝날 때) "더 궁금하신 점은 없으실까요? 이용해 주셔서 감사합니다. ㅇㅇㅇ였습니다."
- (부정적으로 끝날 때) "불편 드려 다시 한번 죄송합니다. 더 나은 서비스로 찾아뵙겠습니다. ㅇㅇㅇ였습니다."
