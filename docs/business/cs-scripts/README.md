# PMart 운영자용 상담 대응 문서 (RAG 원고)

PMart 고객센터 상담원이 백오피스 정책 질문(운영자 RAG, `ai-assistant-service`)으로 찾아볼 상담 대응 원고입니다.
고객앱용이 아닙니다.

- 문서 버전: 0.1
- 작성일: 2026-11-09
- 기준: PMart 업무 문서(`docs/business/*-business-logic.md`)와 ADR. 문서에 근거가 없는 운영 기준은 `[결정 필요]` 로 남겼습니다.

## PMart 상담의 전제

| 항목 | PMart |
|---|---|
| 상품 준비 | PMart 가 운영하는 **MFC(도심 물류센터)** 가 피킹·포장한다. 준비·포장 상태 확인은 MFC(센터 관리자)와 백오피스 화면으로 한다 |
| 배송 | 라이더가 MFC 에서 포장을 인계받아 고객에게 전달한다 |
| 주문 | 회원만 결제한다. 배송지의 지정 MFC 재고로만 주문한다. 결제는 토스페이먼츠 |
| 취소 | 취소 버튼·상담 요청은 **요청 접수**다. MFC 출고 중지 확인과 결제 취소 결과가 나와야 완료다 |
| 결품 | 피킹 중 모자라면 사전 선택과 관계없이 그 품목만 부분 취소·환불한다(ADR-0049) |
| 반품·교환 | 정해진 기한·비용 규칙이 있다(확정 정책, [09](09-return-exchange.md)) |
| 자율 취소·오배송 | 고객 자율 취소는 상품준비 전까지, 확인된 오배송은 새 발송과 회수를 동시에(ADR-0052) |
| 보상 | 쿠폰·프로모션은 1차 구현에서 제외(사용자 확정 2026-10-19). 승인 없는 임의 보상금은 하지 않는다 — 보상 기준은 `[결정 필요]` |

## 작성 규칙

- **지위 태그**: 절 제목 끝에 붙입니다. RAG 가 이 태그로 근거의 지위를 표시합니다.
  - `[확정 정책]` — PMart 업무 문서의 확정 정책을 그대로 옮긴 것(근거 문서를 적음)
  - `[채택 설계]` — PMart 업무 문서의 채택 설계
  - `[설계안]` — 상담 대본·절차 초안. 아직 운영 승인 전
  - `[결정 필요]` — 운영 기준이 없거나 정해야 하는 것
- **청크 경계**: RAG 는 제목 단위로 절을 나누고 표·목록은 통째로 묶습니다. 상황 하나를 절 하나로 두었습니다.
- 대본의 `ㅇㅇㅇ` 은 상담원 이름, `000` 은 주문번호·금액·시각 등 바꿔 넣을 값입니다.

## 용어

| 용어 | 뜻 |
|---|---|
| MFC | PMart 도심 물류센터. 피킹·포장·라이더 인계를 한다 |
| 센터 관리자 | MFC 운영 책임자(백오피스 역할 `MFC_SUPERVISOR`) |
| 피킹 / 포장 | MFC 에서 상품을 꺼내 담는 일 / 봉투·박스에 담아 봉하는 일 |
| 결품 | 피킹 때 상품이 모자라거나 파손돼 주문 수량을 채우지 못함 |
| 인계 | MFC 가 포장을 라이더에게 넘김. 인계된 수량은 출고 전 취소가 아니라 회수·반품으로 처리 |
| 출고 중지 | 취소 요청을 받은 MFC 가 아직 인계하지 않은 포장을 멈춤 |
| 상품준비 | 현장이 실제 주문 준비를 시작한 주문 상태 |
| 배송 시간대 | 고객이 고른 배송 슬롯(예약배달 포함) |
| 회수 배차 | 잘못 전달되거나 반품할 상품을 거둬 오도록 라이더를 배정 |
| 재배송 | 교환 승인 건에 한해 새로 피킹·포장해 다시 보냄 |
| 사건(Case) | 상담·문제를 묶어 관리하는 백오피스 기록 단위(case-service) |
| PG 부분 취소 | 원결제에서 해당 상품·수량 금액만 결제를 취소하는 것 |
