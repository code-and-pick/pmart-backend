## 2. 고정한 설정(dev+회귀로 고름 — `config.json` sha256 17325c147df2, final 전후 같음)
- 운영자 검색: POLICY 문서 점수 ×1.5(상위 20 안에서 다시 정렬). 고객 검색은 가중치 없음.
- **ES 종료 규칙: 핵심어 비율 ≥ 0.7 그리고 1·2위 상대 점수 차 ≥ 0.1**(raw BM25 기준 — 가중치 점수로 판정하지 않음). 끝낼 때 **상위 3 문서 카드**를 돌려준다(계획 §2-2).
  - 1위 청크 하나만 돌려주면 dev+회귀에서 '잘못 끝냄 0' 규칙이 하나도 없었다(`report-dev.md` "돌려주는 방식 비교").
  - 점수 차이만 쓰는 규칙은 dev+회귀에서 gap≥3 이 54건 종료 중 17건 잘못 끝냄(근거 없음 수락 N02·W02·W03·ON01-1, 잘못된 근거 13) — 채택 안 함.
- 넘긴 질문: 질문 임베딩 → BM25+벡터 RRF 상위 3. **벡터 1위 코사인 < 0.58 이면 답변 불가.**

## 5. 판단(실측 기준)과 아직 확인하지 않은 것
- 실측: 핵심어 비율 + 상대 점수 차 규칙과 상위 3 카드 반환으로 **dev·회귀·final 모두 잘못 끝냄 0**, 종료 10~44%. 점수 차이만으로는 안전하지 않다.
- 실측: 새 문항에서 벡터 검색이 BM25 가 놓친 근거를 많이 되찾는다(final 운영자 근거 1위 5→9). 그러나 **코사인 기준 답변 불가 판정은 경계에서 흔들린다**(CG13 0.587 vs 0.58).
- 가설(확인 안 함): 1위 청크 하나가 아니라 카드 3개를 돌려주는 것이 화면·사용자에게 충분한지, ③ 생성의 실제 호출 수·시간, LAN 의 동시 부하에서의 지연.
- 다음 후보: RRF 대신 벡터 순위를 살리는 합치기(가중 RRF 등), 답변 불가 판정에 코사인 외 지표(핵심어 비율) 더하기 — 새 dev 질문군으로 정하고 새 final 로 다시 검증해야 한다(이번 final 은 이미 썼다).
