## 2. 발췌로 떨어진 두 질문 — 원인

같은 근거(LAN 이 돌려준 인용 5개)와 같은 시스템 지시문으로 PC 2 `qwen3:4b` 를 직접 불러 재현했다(온도 0.2, JSON).

| 질문 | 검색된 근거 | 생성 답 | 결과 |
|---|---|---|---|
| 상담원이 고객 연락처 원문을 보려면? | cs-scripts 본인 확인 2·Commerce 14장 2·**ADR-0062 "배경"** — 답인 ADR-0062 결정 3·4·5 가 상위 5개에 없음 | 1회: JSON 모양이 틀림 / 2회: "주문 확인을 통해 **본인 확인을 거쳐야**" — 지어낸 절차 | 인용 검사가 막음 → 발췌 |
| 고객이 앱 알림을 끌 수 있나? 푸시도? | ADR-0064 결정 1·결과·머리, cs-scripts 10, Commerce 15.1 — **결정 3(끌 수 없음)이 없음** | 2회 모두 "고객이 앱 알림을 **끌 수 있습니다**" — 원문과 반대 | 인용 검사가 막음 → 발췌 |

- 인용 검사는 제 몫을 했다(틀린 답을 내보내지 않음). 고칠 곳은 **검색** — ADR 의 "결정 > N" 청크가 질문과 멀다.
- 원인 추정: 청크 임베딩 입력이 `절 경로 + 본문` 인데 ADR 결정 청크의 절 경로는 "결정 > 3" 뿐이라 **무슨 ADR 인지(제목)가 벡터에 없다**(`KnowledgeIngestor` 246행).

## 3. 흐름 문서 "확정 정책 근거 없음" 꼬리표

- manifest 가 흐름 문서 5개를 문서 통째로 `authority: PROPOSAL` 로 둔다. 확정·채택 근거가 하나도 없으면 답 앞에 꼬리표가 붙는다(`ExtractiveComposer.NO_SETTLED_PREFIX`).
- `flows/employee-account-provisioning.md` 는 ADR-0056(승인)과 BO-01(사용자 결정 2026-11-15)을 옮긴 흐름이고 구현·LAN 배포됐다 → **이 문서만 `ADOPTED_DESIGN`** 으로 올림. 다른 흐름 문서 4개는 근거가 문서마다 달라 그대로 둠(필요하면 문서별로 판단).
- 지위만 바뀌고 임베딩 입력은 그대로라 재색인 때 캐시를 써서 빠르다(PC 1 의 #19 재색인처럼 수 분).

## 4. 간헐 503 (`DEPENDENCY_UNAVAILABLE`)

- 지난 1시간 LAN 로그(es-logs)에 4건. 같은 질문이 한 번은 200, 한 번은 2.6초 만에 503 — 시간 초과(25초)가 아니다.
- 로그가 `dependency failure DependencyFailure` 만 남겨 Ollama 오류인지 응답이 비었는지 알 수 없었다 → 두 서비스에 `FailureSummary` 를 넣어 **예외 이름 연쇄 + 우리 고정 문구 + HTTP 상태**를 남긴다(다른 예외 메시지는 모델 응답이 섞일 수 있어 남기지 않음). 배포 뒤 다음 503 에서 원인을 본다.

## 5. 새 문항 7개 기준점 (`report-1-new7-before.md`)

- 채점은 7/7 이지만 **A08(알림 끄기)·A09(푸시)·A10(연락처 원문)은 발췌 답**이다. 발췌 답은 원문을 그대로 보여 주므로 사실 글자가 들어 있으면 정답으로 센다 — 생성이 틀렸다는 사실이 가려진다. 검색을 고친 뒤에는 "생성 정답 수"를 같이 본다.
