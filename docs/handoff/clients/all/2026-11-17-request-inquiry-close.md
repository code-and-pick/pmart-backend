# 요청 — 문의 닫기·상담 종료 (case-service 0.19.0)

보낸 영역: backoffice
받는 곳: pmart-clients 고객앱(문의 상세)·라이더 앱(라이더 문의)·backoffice 웹(문의 상세 — 상담원·지원센터)
상태: case PR 대기(병합·배포는 PC 1).

## 정한 것 (사용자 2026-11-17 "그 표대로 진행해, 다시 열기는 빼고" — 업무 원문 Commerce §14.2-5)
- **고객·라이더 본인**이 "상담 종료"를 확인하고 닫는다(원문 "상담 종료 선택은 확인 후 대화 종료로 기록"). 답변 전에도 된다("해결됐어요").
- **답변 역할 직원**도 닫을 수 있다 — 고객 문의(상담원이 남긴 전화·채팅 접수 포함) = 상담원, 라이더 문의 = 지원센터. **사유 필수**(2~500자), 사유는 직원에게만 보이고 고객에게는 "상담원이 종료함"만. 관리자는 보기만(닫기 403).
- **자동 닫기·다시 열기 없음** — 닫힌 문의는 기록으로 남고, 더 묻고 싶으면 새 문의.
- 닫아도 내용·답변은 계속 볼 수 있다. **상담 종료는 거래 종결이 아니다** — 주문·클레임·다른 접수 건은 그대로.
- 닫으면 답변·사진 보완이 막힌다(409 INQUIRY_CLOSED).

## API
`POST /api/v1/inquiries/{inquiryId}/closures` (Idempotency-Key·X-Source-System)
- 고객: `{ "score": 1~5, "comment": "…" }` 둘 다 선택 — 닫으면서 만족도. 답변을 받은 문의만(아니면 400), 이미 남겼으면 409 `ALREADY_RATED`. 만족도 없이 닫고 나중에 `POST …/satisfaction` 으로 남겨도 된다.
- 라이더: `{}` (만족도 없음).
- 직원: `{ "reason": "중복 문의 — 다른 문의로 안내" }` (필수, 2~500자). score 를 보내면 400.
- → 200 문의 상세. 새 칸 `closedAt`·`closedByType`(CUSTOMER·RIDER·STAFF)·`closeReason`(직원에게만). 이미 닫힘 409 `INQUIRY_CLOSED`, 남의 문의 404, 역할 없음 403.

## 화면 제안
- 고객앱 문의 상세: "상담 종료" 버튼 → 확인 창(“종료하면 이 문의에 더 답할 수 없어요. 더 물어볼 게 있으면 새 문의를 남겨 주세요”) + 답변이 있으면 별 1~5·한 줄(선택) → 닫기. 닫힌 문의는 "종료됨"(STAFF 면 "상담원이 종료함").
- 라이더 앱: 같은 확인 창(만족도 없음).
- 백오피스 문의 상세(상담원·지원센터): "문의 닫기" — 사유 필수 칸. 목록 거르기 status=CLOSED. 관리자에게는 버튼 없음.
