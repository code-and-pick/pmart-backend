# 요청 — 접수 건 메모 (case-service 0.10.0)

보낸 영역: backoffice
받는 곳: pmart-clients backoffice 웹(접수 건 상세 — 지원센터·상담원·관리자)
상태: case PR 대기(병합·배포는 PC 1).

> 화면 용어(2026-11-16 사용자 결정): 사건(case) = "접수 건", 닫기 = 처리 끝내기, 재개 = 다시 처리하기, 의무 = 후속 처리. 아래 API 이름은 백엔드 이름 그대로.

## 1. 정한 것 (사용자 2026-11-16 "고친 안")
- 접수 건에 **메모를 덧붙인다** — 예: 고객과 통화한 결과, 교대 뒤 전임이 늦게 알게 된 사실(업무 원문: 늦은 보고는 버리지 않고 원래 건에).
- 남길 수 있는 사람: 그 접수 건을 볼 수 있는 **본사 직원**(관리자·지원센터·상담원). 센터 관리자는 아직 못 남긴다.
- **처리 끝난 접수 건에도** 남길 수 있다. 상태는 바뀌지 않는다(근거가 뒤집혔으면 따로 "다시 처리하기").
- **고치기·지우기 없음** — 잘못 쓰면 정정 메모를 새로. 개인정보(전화번호·주소)를 쓰지 않는다 — 실수로 쓰면 **관리자가 가린다**(사유 필수, 글은 지우고 누가·언제·왜 가렸는지는 남는다).

## 2. API
- 남기기 `POST /api/v1/cases/{caseId}/notes` `{text}`(1~500자), `Idempotency-Key`·`X-Source-System` → 201 메모. 400 빈 글 / 403 권한 없음 / 404 못 보는 접수 건.
- 목록 `GET /api/v1/cases/{caseId}/notes` → `items[]`(오래된 것부터): `noteId·text·authorId·createdAt·masked·maskedAt·maskedBy·maskReason`. 가린 메모는 `text` null.
- 가림 `POST /api/v1/cases/{caseId}/notes/{noteId}/maskings` `{reason}` — 관리자만(403), 사유 없으면 400. 이미 가린 메모는 그대로 돌려준다.

## 3. 화면에 바라는 것
- 접수 건 상세에 "메모" 칸 — 입력란(500자, **"개인정보(전화번호·주소)는 쓰지 마세요"** 안내)과 목록(누가·언제). 이력과 함께 시간순으로 보여도 좋다.
- 가린 메모는 "관리자가 가린 메모(사유)"로 표시. 관리자에게만 "가리기"(사유 입력).
- 처리 끝난 접수 건에서도 입력란을 둔다.

## 4. 계약
