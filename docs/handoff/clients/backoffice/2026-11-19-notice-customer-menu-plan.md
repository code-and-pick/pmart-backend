# 알림 — 백오피스 "고객" 메뉴 계획(조회만, 3단계)

보낸 영역: backoffice
- 작성: pmart-backend PC 2, 2026-11-19
- 근거: 사용자 2026-11-19 "백오피스 쪽에 고객 관리 메뉴도 필요하지 않을까" → PC 2 추천안 "응 그대로 진행해". 참고로 본 Eum 백오피스 회원 관리(이름·이메일 검색, 연락처 원문 목록)는 PMart 업무 원문 개인정보 규칙(목적별 제한·원문은 사유 뒤)과 맞지 않아 찾기·연락처 방식은 PMart 규칙으로, 가입 방식 배지·인증 여부·가입일 칸은 가져옴.
- 상태: **계획** — 원천 API 가 아직 없다(customer CU-4·CU-3, claim CL-7 → PC 1, bff BF-2 → PC 2). 나오면 버전·필드를 다시 알림.

## 1단계(먼저)
- 메뉴: **고객센터 → 고객**(CS_AGENT·OPERATOR_ADMIN).
- 찾기: 고객번호·전화번호·주문번호 **완전 일치만**(이름 검색·전체 목록 없음).
- 상세 머리: 가린 이름 · 고객번호, 가입 방식 배지(Google·Kakao·Naver), 휴대폰 확인 여부, 가입일, 계정 상태.
- 상세 탭: 최근 주문·클레임·문의·접수 건(각 줄 → 기존 상세). 칸마다 원천을 못 읽으면 "확인 못 함"(0 아님).
- 원문 보기: 사유 입력 → 열람 기록 뒤 원문(라이더 상세와 같은 방식).

## 2단계
- 동의 현황·저장된 배송지(가린 값) 보기, 상담원 접수 이력, 주문·문의 상세에서 "이 고객 보기" 링크.

## 3단계(규칙 정해진 뒤에만 — 지금 만들지 않음)
- 상담원의 연락처·주소 대리 변경, 운영 제한, 쿠폰.

## 그 전에
- 지금은 통합 조회(고객 ID → 주문)로 대신. 화면 틀(메뉴 자리·찾기 칸·탭)은 목으로 먼저 만들어도 됨 — 계약에 없는 것은 부르지 않는다.
