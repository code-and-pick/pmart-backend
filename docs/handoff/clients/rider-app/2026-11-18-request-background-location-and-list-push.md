# 요청·알림 — 라이더 앱: 운행 중 백그라운드 위치, 배차 제안·새 배달 푸시

보낸 영역: delivery
- 작성: pmart-backend PC 5(delivery), 2026-11-18
- 대상: pmart-clients `apps/rider_app`
- 사용자 2026-11-18: "신규배차 켜놓고 앱 닫으면 배차알림이 안 뜨네" → 일반 모드도 알림 **"보냄 — 묶어서"**, 백그라운드 위치 **"보내게 함"**

## 1. 운행 중 백그라운드 위치 (요청)
- 배차(AI 추천 제안·일반 모드 새 배달 알림 모두)는 **최근 2분 안에 위치를 보낸 라이더만** 후보로 본다. 앱을 닫거나 화면이 꺼지면 위치가 끊겨 제안도 알림도 오지 않는다.
- **운행 중(ON_DUTY)일 때만** 안드로이드 포그라운드 서비스(상시 알림 "운행 중 — 위치 전송 중")로 백그라운드에서도 `POST /riders/me/locations` 를 계속 보내 주세요(지금과 같은 주기·묶음). 운행을 끄면 멈춤. 위치 권한은 "항상 허용"이 필요하면 운행 시작 때 안내.
- 서버 변경 없음.

## 2. 배차 제안 푸시 (백엔드 PR #191 — 배포 전)
- 11-17 회신(`2026-11-17-reply-rider-push-send.md`)의 배차 제안 푸시가 서버에 빠져 있었다 — 다시 올림. data `type` DISPATCH_OFFER·offerId·deliveryId·expiresAt, 채널 `dispatch_offer`, HIGH, TTL 만료까지, tag dispatch_offer. 누르면 `GET /offers`.

## 3. 일반배차모드 새 배달 푸시 (백엔드 PR #192 — 배포 전)
- 일반 모드·신규배차 켬·위치가 살아 있는 라이더의 배달리스트에 **지난 알림 뒤 새 배송**이 보이면 푸시(라이더마다 **1분에 한 번까지** — 묶어서).
- 알림함에는 없음. data `type` **DELIVERY_LIST**·`newCount`·`sentAt`, 제목 "새 배달이 있어요", 본문 "배달 목록에 새 배달 N건이 올라왔어요.", 채널 `dispatch_offer`, HIGH, TTL 60초, tag delivery_list(앞 알림을 덮음).
- 앱: 누르면 배달리스트 화면을 열고 `GET /delivery-list` 다시 읽기. 이미 목록을 보고 있으면 알림 없이 목록만 새로.
