# ADR-0060 상품준비 뒤 고객센터 취소는 하지 않는다 — ADR-0052 결정 2 대체

- 상태: 승인 (2026-11-13, 사용자 — PR #8 검토 H1 답 "고객센터 취소 못하는 걸로 정할 거야."(delivery 영역 요청 `service-requests/claim-service.md` CL-D1 — PR #8 에 있음), 범위 확인 "상품준비 뒤~인계 전만 없앰"(추천안))
- 대체: ADR-0052 **결정 2**("상품준비 뒤 취소: 고객센터 문의로 접수, MFC 출고 중지가 확인된 미인계 수량만 취소"). 사용자 2026-11-08 "중도 고객 취소는 아주 예외 — 고객센터를 통해서만 제한적으로 허용"(case-service 요청 R-2)도 이 ADR 로 거둔다.
- 그대로: ADR-0052 결정 1(고객 자율 취소 = 상품준비 전, 앱 주문 내역)·3~5(오배송). **D-7**(라이더 픽업·배달 시작 뒤 고객 요청은 고객센터 경유, 회수비 9,000원 고객 부담·회사 잘못이면 면제 — `claim-service.md` CL-1)은 그대로다 — 인계 뒤에는 상품이 라이더에게 있어 "취소"가 아니라 회수·반품으로 다룬다.
- 관련: `docs/business/flows/cancel-vs-handover.md`, `contracts/states/order-states.md`, ADR-0046(피킹 뒤 취소 복귀), ADR-0049(결품 부분 취소), `service-requests/case-service.md` R-2, `service-requests/mfc-fulfillment-service.md` F-2(PR #8 에 있음)

## 배경
- ADR-0052 2번은 상품준비(주문 `PREPARING`) 뒤에도 고객센터가 출고 중지를 확인해 미인계 수량을 취소하는 길을 열어 두었다. 구현은 없었다(claim-service 는 고객 앱 접수만 받는다 — "운영자·CS 접수는 아직 없습니다").
- 배차를 점원 요청으로 앞당기는 결정(F-2 — 피킹(또는 픽업) 시작 전 포장 소요시간 입력 → 배차 요청)과 함께, 준비 중 주문을 고객 요청으로 멈추면 배차·라이더 쪽 되돌림(PR #8 H1)이 늘어난다. 사용자는 이 경로를 없애기로 했다.

## 결정
1. **상품준비(`PREPARING`) 뒤 ~ 라이더 인계 전**: 고객 요청에 의한 취소는 **어느 경로로도 받지 않는다**(고객 앱·고객센터 모두). 고객센터는 취소를 접수하지 않고 "받으신 뒤 반품·교환" 또는 아래 2의 회수로 안내한다.
2. **라이더 인계 뒤(픽업·배달 시작 뒤)**: D-7 그대로 — 고객센터 경유 회수 요청, 회수비 9,000원 고객 부담(회사 잘못이면 면제), 상품 환불은 회수품 검수 뒤(CL-1).
3. **남는 중지 경로(고객 요청이 아님)**: 시스템 취소만 — 결품(전체·부분, ADR-0049), 작업 거절. 주문 `PREPARING` 도 받는다(ADR-0046 복귀 그대로).
4. **상품준비 전 취소**: 고객 앱 자율 취소(ADR-0052 결정 1) 그대로.

## 적용
- claim-service: 코드 변경 없음 — 지금도 고객(CUSTOMER) 접수만 받고, 고객 취소는 `CONFIRMED` 일 때만(`ClaimRules.checkFullCancel`). 계약 `CreateClaimRequest.channel` 의 `CS`·`OPERATOR` 값은 반품·회수(CL-1) 때 쓸 수 있어 남긴다.
- case-service 요청 R-2(진행 중 주문 고객센터 취소)는 거둔다.
- delivery-dispatch-service: 고객센터 취소가 없어도 시스템 부분 취소(결품)가 남으므로, 피킹 전 중지를 주문 전체 중지로 보면 안 된다(PR #8 재검토 1번 그대로).
- 고객 안내 문서(`docs/business/customer-faq/02-cancel.md`·`03-delivery-status.md`, 고객 RAG 원문)에서 "상품준비 뒤 고객센터로 취소 요청" 문구를 고친다. LAN 고객 RAG 는 다시 색인해야 반영된다(`lan.sh rag-ingest-customer`).

## 결과
- 고객: 상품준비가 시작되면 취소할 수 없다는 규칙이 하나로 분명해진다. 대신 마음이 바뀐 고객은 받은 뒤 반품(변심 반품 규칙)으로 간다.
- 운영: 고객센터가 준비 중 주문의 현장 중지를 판단할 일이 없다. 배차·현장 되돌림은 시스템 취소(결품)로만 생긴다.
- 남은 것: 인계 뒤 회수 요청(D-7)을 고객센터가 어떻게 접수하는지는 CL-1·case-service 구현 때 정한다.
