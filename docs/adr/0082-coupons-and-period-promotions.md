# ADR-0082 쿠폰·기간 할인 도입 — promotion-service 활성화

- 상태: **승인** (2026-11-20)
- 사용자 결정 2026-11-20: "쿠폰 기능 만들고싶어. 그리고 프로모션으로 해당 상품들 전체적으로 적용하는 것까지" → 범위 "기간 할인+쿠폰 둘", 쿠폰 받기 "앱에서 내려받기·운영자가 지정 발급·가입 축하 자동 발급", 복원 "전체 취소만 복원", 승인 "승인 필요", 할인 대상 "상품 목록 지정·카테고리 통째", 표시 "상품 카드·상세·장바구니 모두", 가입 쿠폰 "행사로 설정", 역할 "새 역할 MARKETING".
- **대체**: `docs/business/Commerce-business-logic.md` 1.0 "프로모션·할인·쿠폰은 1차 구현에서 제외"(사용자 확정 2026-10-19)를 이 범위만큼 바꾼다. 원문은 고치지 않고 이 ADR 이 우선한다. 계산 규칙은 원문 부록 C.1 §8.5·8.6·8.8(과거 확정 정책)을 그대로 쓴다.

## 결정
1. **범위 — 기간 할인(상품) + 장바구니 쿠폰.** 상품 쿠폰·수량 오퍼(1+1·N개 할인)·배송비 쿠폰·증정·마감 할인은 이번에 하지 않는다.
2. **계산 순서(부록 C §8.5 그대로)**: 기본가 → 기간 할인 → 장바구니 쿠폰. 상품 쿠폰 단계는 비워 둔다.
   - 같은 SKU 에 걸린 기간 할인이 여럿이면 **고객에게 가장 큰 할인 1개**(중첩 없음).
   - 정률은 원 미만 버림. 할인 뒤 단가가 0 보다 작아지지 않는다.
   - **최소 주문금액 15,000원·무료 배달 30,000원 판정은 기간 할인 뒤·쿠폰 전 상품액**(§8.5 3).
   - 장바구니 쿠폰 할인은 대상 품목 금액에 비례 안분, 원 미만 버림, 잔여 원은 금액이 가장 큰 품목(동률은 주문 품목 순서). 품목 할인 합계는 그 품목 금액을 넘지 않는다.
   - 주문 1건에 장바구니 쿠폰 1장.
3. **기간 할인 대상**: 상품(SKU) 목록 지정 또는 카테고리 통째(그 카테고리 아래 상품 — 행사 기간에 새로 들어온 상품 포함). 할인은 정률(%) 또는 정액(원). 시작·끝 시각.
4. **장바구니 쿠폰**: 정액 또는 정률(+ 최대 할인액), 최소 주문금액(쿠폰 전 상품액), 사용 기간(고정 기간 또는 발급 후 N일), 총 발급 수량, 1인 발급 한도.
   - 받는 방법(행사마다 하나): **DOWNLOAD**(앱 내려받기 — 총 수량·1인 한도 확인, 마지막 1장은 한 명만), **ADMIN**(운영자가 특정 고객에게 — 보상 등, CL-5 배차 불가 2,000원 쿠폰도 이것으로), **SIGNUP**(가입 축하 자동 — 같은 휴대폰 번호 재가입에는 다시 주지 않음).
5. **쿠폰 사용·복원**: 주문 결제 진입 때 점유(hold) → 결제 성공·주문 확정 때 사용 확정 → 결제 실패·만료면 점유 해제. **전체 취소 확정 뒤에만 복원** — 원래 사용 기간 안일 때만(연장·새 발급 없음). 부분 취소·반품은 쿠폰 그대로 사용 처리, 환불은 주문 당시 품목별 순액(할인 안분 뒤) 기준.
6. **승인**: 기간 할인·쿠폰 행사는 승인 종류 **PROMOTION**. 만든 사람이 아닌 승인자가 승인해야 발효. 발효 뒤 끝내기(조기 종료)도 승인.
7. **역할 MARKETING 신설**: MARKETING 이 행사를 만들고, 다른 MARKETING 또는 OPERATOR_ADMIN 이 승인(본인 승인 불가). 지정 발급(ADMIN)은 MARKETING·CS_AGENT·OPERATOR_ADMIN.
8. **표시**: 상품 카드(검색·홈·카테고리)·상세·장바구니·주문서에 정가·할인가·할인율. 목록 정렬 "할인율순"은 이번에 하지 않는다.
9. **정본**: promotion-service — 행사·쿠폰 발급·점유·사용·복원·행사 수량. 가격 계산은 pricing(견적이 promotion 의 유효 할인·쿠폰을 받아 계산), 주문 금액 확정·스냅샷은 order, 점유·확정·해제·복원 조율은 orchestration(checkout 사가 S1-e, 취소 사가 S3-f).

## 나누어 만들기
1. promotion-service 기본 — 행사(기간 할인·쿠폰) 만들기·승인 반영·조회, 쿠폰 내려받기·지정 발급·내 쿠폰함, 유효 할인 조회(SKU 목록), MARKETING 역할·PROMOTION 승인 종류.
2. pricing 견적 — 기간 할인·장바구니 쿠폰 계산·안분(`discountShare`·`appliedStages`).
3. order·orchestration — 주문서 쿠폰 선택, 점유·확정·해제, 전체 취소 복원, 금액 스냅샷. claim 환불이 순액 기준인지 확인.
4. 표시 — 할인가 사건(`PromotionPriceChanged` 등)으로 검색 색인·홈·상품 상세 카드.
5. 가입 쿠폰(SIGNUP)·CL-5 보상 쿠폰.
6. 화면 — 백오피스(PC 2 — 행사 만들기·승인·발급) 요청서, 고객 앱 handoff(쿠폰함·내려받기·주문서 쿠폰·할인가 표시).

## 진행
- 2026-11-20 1단계 LAN 배포(80d1a952).
- 2026-11-21 2·3단계: pricing 0.2.0 견적 할인, order 0.18.0 주문서 쿠폰·결제 진입 점유·주기 작업(확정·해제·복원), claim 환불(쿠폰 뺀 상품액·결품 부분 환불 할인 안분). 사가(orchestration)는 쿠폰을 모른다 — order 가 맡는다(flows 문서 S1-e·S3-f).
- 2026-11-21 4단계 할인가 표시: promotion 이 기본가 사본(PriceVersionEffective)으로 SKU 마다 지금 표시 할인을 30초마다 다시 계산해 바뀐 것만 `SkuDisplayDiscountChanged`(토픽 `commerce.sku-display-discount.v1`, compact). 검색(Logstash 색인 `sku-discounts` → 결과 대표 SKU)·홈(storefront 사본)은 가격 사본과 priceVersion 이 같고 끝 전일 때만 할인가. 상세·장바구니는 pricing `/prices` 가 promotion 을 바로 묻는다(못 읽으면 정가 + discountAvailable=false). 가격순 정렬·가격 범위는 기본가 그대로. 계약 pricing 0.3.0·cart 0.4.0·storefront 0.8.0·search 0.6.0.

- 2026-11-21 5단계: **가입 축하 쿠폰** — customer-service 가 로그인 단계 휴대폰 확정(ADR-0074 VERIFIED)마다 `CustomerIdentityVerified`(stage SIGNUP·PROFILE, `signupKey` = 번호 HMAC — 비밀값 `pmart.customer.identity.signup-key-secret`, 번호 원문·해시는 싣지 않음). promotion 이 stage SIGNUP 을 받아 진행 중 SIGNUP 쿠폰 행사마다 한 장, 같은 키에는 다시 주지 않음(`signup_grant` — 사용자 2026-11-21 "계속 막기" → 같은 날 "추천대로" **지급 후 5년**: 탈퇴 뒤에도 5년 보관 후 파기, 처리방침 2026-11-21.2 판·전 고객 재동의). 로그인 단계 확인을 처음 거치는 기존 계정도 받는다. **CL-5 보상 쿠폰** — promotion 이 OrderCancelled(cancelReason DISPATCH_UNAVAILABLE)를 받아 주문마다 한 번(`compensation_grant`), 설정 `pmart.promotion.compensation.dispatch-unavailable-promotion-id` 의 COUPON·ADMIN 진행 중 행사에서 1인 한도 없이 한 장. 행사가 없으면 PENDING → 1분마다 다시. 처음 켤 때 지난 취소는 소급하지 않음(binding latest). LAN 보상 행사 = 2,000원·받은 날 포함 30일·쿠폰 최소 주문 없음(사용자 2026-11-21).

- 2026-11-24 덧붙임(promotion 0.3.0 — 사용자 "행사 대상에 테마도 추가"·"직원 지정 발급 … 고객 id 를 넣는 칸", 세부 "추천안대로 진행"): ① 기간 할인 대상에 **진열 테마 THEME**(storefront 편성 테마 sectionId) — 그때 게시된 진열에서 그 테마 상품의 모든 옵션, 테마 상품이 바뀌면 다시 승인 없이 따라감(카테고리와 같음), 진열에서 빠지면 할인도 멈춤, 자동 랭킹 테마 제외, 테마 노출 기간은 보지 않음. promotion 이 1분마다 storefront 내부 조회로 사본을 받는다(진열 변경 → 할인 반영 최대 약 1분 30초). 원문 Commerce §6.3·6.4 "일반 테마는 할인 권리를 만들지 않는다"를 같은 날 고침 — 권리는 행사가 만든다. ② 지정 발급(ADMIN) 쿠폰을 만들 때 **받을 고객**(≤100명·사유) — 승인 뒤 시작 시각이 되면 1분 안에 발급(지정 발급과 같은 규칙, 발급한 사람 = 행사를 만든 직원), 시작 전에 끝나면 발급 안 함, 승인 요약에 받을 고객 수.

## 결과
- service-map promotion-service 를 "1차 비활성"에서 활성으로. 원문 1차 제외 문구와 다른 부분은 이 ADR 을 따른다.
- 남은 정책(이번에 정하지 않음): 상품 쿠폰·오퍼, 부분 반품 때 쿠폰 할인 환수, 쿠폰 남용 제한.
