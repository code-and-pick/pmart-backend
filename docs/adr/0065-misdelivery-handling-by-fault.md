# ADR-0065 확인된 오배송은 귀책에 따라 처리한다 — 고객 잘못은 다시 배송(200m 넘으면 9,000원), 라이더 잘못은 고객이 환불·재발송 중 고른다

- 상태: 승인 (2026-11-16, 사용자 — "오배송이 고객 잘못이면 200m이내는 기사가 다시 배송해주고, 200m 이상 차이나면 추가금 발생하고 원래 집에 배송해줌. 오배송이 라이더 잘못이면 환불 또는 다시 피패킹 후 배송이야." 세부는 PC 5 추천안을 사용자가 고름 — 아래 각 결정에 표시)
- 대체: **ADR-0052 결정 4**(확인된 오배송은 늘 회수 + 새 발송)를 귀책별로 바꾼다. ADR-0052 결정 3(확인 조건)·5(같은 피해 수량을 새 발송과 환불로 겹치지 않음)는 그대로.
- 근거 원문: Delivery §9.2 "주소 불일치 — 고객 주소 오입력, 라이더 오배송, 지도·시스템 오류 구분 / 기존 기사 추가 이동 또는 회수·재배송 여부 승인 / (배송완료인데 변경요청 200m 이상 차이나면 회수재배송 9000원 or 회수 및 취소환불)", §9.3 "오배송 — 라이더 귀책이면 배달료 미지급, 회수 가능성·상품 상태 확인 후 환불·재배송 결정", BackOffice BO-20 "결제 후 주소 변경 금지를 우회하는 새 주소 입력 기능은 두지 않는다".
- 관련: `docs/business/flows/misdelivery-recovery-reshipment.md`, case-service R-7(오배송 확인 기록), delivery DD-2(회수), orchestration 재발송 사가(2026-11-16).

## 배경
2026-11-16 구현은 오배송이면 늘 "회수(MFC 반납) + 같은 상품 새로 피킹해 재발송"이었다. 실제로는 귀책이 고객(주소 오입력 등)인 경우가 많고, 그때 상품은 멀쩡히 근처에 있다 — MFC 로 되가져와 새로 보내는 것은 낭비다.

## 결정
1. **귀책 기록**: 상담원·지원센터가 오배송을 확인할 때(case MISDELIVERY) 귀책을 `CUSTOMER`(주소 오입력 등)·`RIDER`(라이더 실수)·`SYSTEM`(지도·시스템 오류)으로 기록한다. **SYSTEM 은 라이더 잘못처럼 처리하되 원래 배달료는 지급**한다(회사 쪽 사유 — 사용자 2026-11-16 추천 선택).
2. **고객 잘못 — 실제 집이 전달 위치에서 200m 안**: **원래 라이더**가 잘못 둔 상품을 가져가 실제 집에 다시 배송한다. 고객 추가금 없음, 라이더 추가 운행료 없음(원래 배달료는 정상 지급). 원래 라이더가 다른 배송 중이거나 받지 못하면 근처 다른 라이더(일반 배달료 표). (PC 5 추천 — 사용자 선택)
3. **고객 잘못 — 200m 이상**: 고객이 **9,000원**(업무 원문 회수재배송 금액)을 **고객 앱에서 추가 결제**하면, 근처 라이더가 잘못 간 같은 상품을 받아 실제 집으로 바로 배송한다(MFC 를 거치지 않고 다시 피킹하지 않음). 고객이 원하면 원문대로 "회수 후 취소·환불"을 고를 수 있다. 결제를 **30분** 안에 하지 않으면 회수 후 취소·환불로 간다. 이때 환불은 **상품값 − 9,000원**(회수비 공제, 0원 아래로 내려가지 않음 — 배달팁·봉투값은 환불하지 않음). (사용자 선택: 금액·방식·앱 결제·30분·상품값 − 9,000원)
4. **실제 집 주소**: 고객 잘못일 때만 상담원이 고객에게 받은 실제 주소를 기록한다(입력·열람 기록 남김 — ADR-0062 방식). 시스템이 주소를 좌표로 바꿔 **전달 위치(원래 라이더가 완료를 누른 곳)와의 거리**를 재고 200m 안·밖을 정한다. 일반 주소 변경 기능은 만들지 않는다(BO-20). (PC 5 추천 — 사용자 선택)
5. **라이더 잘못(SYSTEM 도 같음)**: **고객이 고르고 상담원이 기록**한다 — `REFUND`(전 품목 환불) 또는 `RESHIP`(MFC 에서 다시 피킹·포장해 원래 주소로 — 2026-11-16 재발송 사가, 재고 없는 품목만 부분 환불). 어느 쪽이든 잘못 간 상품은 회수해 MFC 로 반납(DD-2). **원래 라이더 배달료는 지급하지 않는다**(업무 원문 §9.3 — SYSTEM 이면 지급). 이미 지급(PAID)됐으면 자동으로 돌려받지 않고 지원센터 조정 기록만 남긴다. (사용자 선택)
6. 같은 피해 수량을 다시 배송·재발송과 환불로 겹치지 않는다(ADR-0052 결정 5 그대로) — 주문 수량 원장에 남긴다.

## 결과 — 귀책·선택별 흐름
| 귀책 | 조건·선택 | 잘못 간 상품 | 고객 | 라이더 |
|---|---|---|---|---|
| 고객 | 200m 안 | 원래 라이더가 가져가 실제 집으로 | 추가금 없음 | 원래 배달료 지급, 추가 없음 |
| 고객 | 200m 이상 · 다시 배송 | 근처 라이더가 실제 집으로(앱 9,000원 결제 뒤) | 9,000원 | 다시 배송 라이더 일반 표 |
| 고객 | 200m 이상 · 취소·환불(또는 30분 안에 결제 안 함) | 회수 → MFC | 상품값 − 9,000원 환불 | 회수 라이더 일반 표 |
| 라이더 | 재발송 | 회수 → MFC | 새 상품 받음(재고 없는 품목만 환불) | 원래 배달료 미지급 |
| 라이더 | 환불 | 회수 → MFC | 전 품목 환불 | 원래 배달료 미지급 |
| 시스템 | 재발송·환불 | 회수 → MFC | 라이더 잘못과 같음 | 원래 배달료 지급 |

## 정한 값(2026-11-16 사용자)
- 9,000원 결제 대기 30분, 넘으면 회수 후 취소·환불.
- 고객 잘못 + 취소·환불 = 상품값 − 9,000원.
- 지도·시스템 오류(SYSTEM) = 라이더 잘못처럼, 원래 배달료는 지급.
- 이미 지급된 배달료는 지원센터 조정 기록만(자동 공제 없음).
