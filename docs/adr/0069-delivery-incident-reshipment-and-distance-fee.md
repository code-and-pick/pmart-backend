# ADR-0069 배송 중 사고·파손은 새 상품 재발송, 사고 수행료는 간 거리 비율

- 상태: 승인 (2026-11-18, 사용자)
- 근거(사용자 2026-11-18):
  - "1번 진행해. 사고나면 재배송해야지. 음식이 어떤 상태일줄 알고." (백오피스 빈 곳 1번 — 픽업 뒤 라이더 사고)
  - "사고나면 배달료는 이동시점까지의 거리를 계산해서 지급한다." → 계산 방식 "원래 금액을 거리 비율로"
  - "사고 말고 상품 파손(DAMAGED)으로 전달을 못 했을 때도 새 상품으로 재배송할까요?" → "파손도 재배송"
- 관련: ADR-0052(오배송 회수·재발송 동시), ADR-0065(오배송 귀책), 업무 원문 배송 §9.6 "수행 중 상품은 안전한 전달·회수·재배정", BO-20 재배정.
- 대체: 2026-11-17 "그 밖 귀책은 기존대로 수행료 조정"(전달 실패 반납 결정)의 **사고(RIDER_INCIDENT)** 부분. 파손·기타는 그대로 조정.

## 배경
픽업 뒤 라이더가 사고가 나면 지금까지는 "전달 불가 확정 → 상품 반납"만 있었고, 주문은 아무것도 하지 않았다(자동 환불·재발송 없음). 고객 상품은 MFC 로 돌아가고 주문은 사실상 실패로 끝났다. 사고 난 상품은 상태를 알 수 없어 그대로 다른 라이더가 이어서 배달할 수 없다.

## 결정
1. **사고(RIDER_INCIDENT)·파손(DAMAGED)으로 전달 실패가 확정되면 새 상품을 재발송한다**(고객 비용 0원). 오배송 재발송 사가(ADR-0052 결정 4, order-orchestration `reshipment_saga`)를 그대로 쓰고 시작만 다르다 — execution `DeliveryFailed`(delivery.delivery.v1)를 orchestration 이 받는다. 근거 ID = `DF-<실패한 배송 ID>`(실패마다 하나). MFC 재고 확보 → 재발송 작업 지시(kind RESHIPMENT) → 점원 피킹·포장·배차 요청 → 새 배송(약속 = 그 배송 생성 + 50분). 모자란 품목은 그 품목만 부분 환불(ADR-0049).
   - 대상 배송: 일반 배송(FORWARD)과 앞선 재발송 배송(RESHIPMENT·MISDELIVERY_RESHIPMENT). 회수·반납·오배송 다시 배송(잘못 둔 곳 → 실제 집, 원래 상품)·고객 반품 회수는 아니다.
   - 보낼 수량 = 원수량 − 출고 전 취소 − 전달됨(실패한 출고는 전달 0). 오배송 재발송 배송이 사고 나면 오배송 상품이 전달됨으로 세어져 0 이 될 수 있다 — 그때는 상신(수동).
   - 실패한 상품은 지금처럼 반납한다(같은 라이더 또는 다른 라이더 — 2026-11-17 결정). MFC 수령·검수(폐기·재고 복구)는 mfc-inbound.
2. **사고 수행료 = 수락 당시 금액 × min(1, MFC → 사고 지점 도로 거리 ÷ 수락 당시 MFC → 고객 도로 거리)**, 원 미만 버림, 완료와 같은 확정·지급 일정(확정 대기 → 5시간 뒤 확정).
   - 사고 지점 = 실패 등록 시각에 가장 가까운 라이더 위치 점(tracking location-at, 앞뒤 3분). 지원센터가 직접 확정해 등록 시각 근처 점이 없으면 마지막으로 받은 위치(픽업 뒤 점만).
   - 거리는 배차가 쓰는 같은 거리 행렬(카카오모빌리티)로 dispatch 가 잰다(`GET /internal/deliveries/{id}/incident-distance`). 잴 수 없으면(위치·길 없음, 호출 실패) 산정 불가 → 지원센터 조정.
   - 비율은 표 최저 금액(2,600원)보다 낮을 수 있다(사용자가 "원래 금액을 거리 비율로"를 고름 — 표에 다시 넣는 방식이 아님).
3. 파손(DAMAGED)의 수행료는 그대로 산정 불가 → 지원센터 조정(귀책을 사람이 정한다).

## 결과
- 고객: 사고·파손이 나도 새 상품을 받는다. 고객 알림(재발송 안내)은 notification 요청 N-4(아직 없음 — 상담원 안내).
- 라이더: 사고 시 간 거리만큼 바로 받는다(지원센터 조정 없이).
- 남은 것: 고객 안내 알림(N-4), 재발송 출고·배송 화면 문구의 "오배송 재발송"(purpose 값 MISDELIVERY_RESHIPMENT 를 같이 씀 — MFC 계약을 바꾸지 않으려고), 재발송 지연 기한(ADR-0052 남은 것과 같음).
